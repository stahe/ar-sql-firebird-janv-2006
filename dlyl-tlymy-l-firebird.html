    2. دليل تعليمي لـ Firebird

    قبل الخوض في أساسيات لغة SQL، نقدم للقارئ شرحًا حول كيفية تثبيت Firebird SGBD بالإضافة إلى العميل الرسومي IB-Expert.

    2.1. أين يمكن العثور على Firebird؟

    الموقع الرئيسي لـ Firebird هو [http://firebird.sourceforge.net/]. توفر صفحة التنزيلات الروابط التالية (أبريل 2005):

    سيتم تنزيل العناصر التالية:

    firebird-win32
    ملف SGBD لنظام التشغيل Windows
    firebird-net-provider
    مكتبة فئات للتطبيقات .NET تتيح الوصول إلى SGBD دون الحاجة إلى برنامج تشغيل ODBC.
    firebird-ODBC-driver
    برنامج التشغيل ODBC الخاص بـ Firebird

    قم بتثبيت هذه العناصر. يتم تثبيت SGBD في مجلد يحتوي على محتويات مشابهة لما يلي:

    توجد الملفات الثنائية في المجلد [bin]:

    fbguard.exe
    يسمح بتشغيل/إيقاف SGBD
    isql.exe
    العميل الذي يتيح إدارة قواعد البيانات

    تجدر الإشارة إلى أن اسم مسؤول SGBD افتراضيًا هو [SYSDBA] وكلمة مروره هي [masterkey]. تم تثبيت قوائم في [Démarrer]:

    يتيح الخيار [Firebird Guardian] تشغيل/إيقاف SGBD. بعد التشغيل، تظل أيقونة SGBD في شريط مهام ويندوز:

    لإنشاء قواعد بيانات Firebird واستخدامها باستخدام عميل سطر الأوامر [isql.exe]، من الضروري قراءة الوثائق المرفقة مع المنتج في المجلد [doc].

    ومن المثير للاهتمام أن IBExpert يعرض الاستعلامات SQL التي نفذها. وهذا يتيح التعلم في آن واحد لكل من لغة SQL وكذلك اللهجة SQL التي قد تكون خاصة بالبرنامج. يتيح الزر [Commit] تأكيد المعاملة الجارية، بينما يتيح الزر [Rollback] إلغاءها. هنا نقبلها باستخدام [Commit]. وبمجرد القيام بذلك، يقوم IBExpert بإضافة الجدول الذي تم إنشاؤه إلى شجرة قاعدة البيانات لدينا:

    نجد هنا قيد المفتاح الأساسي الذي أنشأناه. يمكننا إضافة قيود أخرى:

    • مفاتيح خارجية [Foreign Keys]
    • قيود سلامة الحقول [Checks]
    • قيود تفرد الحقول [Uniques]

    نشير إلى أن:

    • يجب أن تكون قيم الحقول [ID, PRIX, STOCKACTUEL, STOKMINIMUM] أكبر من 0
    • يجب أن يكون الحقل [NOM] غير فارغ وفريدًا

    لنفتح اللوحة [Checks] ونضغط بزر الماوس الأيمن داخل مساحة تعريف القيود الخاصة بها لإضافة قيد جديد:

    لنحدد القيود المطلوبة:

    يُلاحظ أعلاه أن القيد [NOM<>''] يستخدم علامتي اقتباس مفردة وليس علامتي اقتباس مزدوجة. لن نقوم بتجميع هذه القيود باستخدام الزر [Compile] أعلاه:

    مرة أخرى، يُظهر IBExpert طابعًا تعليميًا من خلال الإشارة إلى الاستعلامات SQL التي نفذها. لننتقل الآن إلى اللوحة [Constraints/Uniques] للإشارة إلى أن الاسم يجب أن يكون فريدًا. وهذا يعني أنه لا يمكن وجود نفس الاسم مرتين في الجدول.

    لنحدد القيد:

    ثم نقوم بتجميعها. بعد ذلك، نفتح لوحة [DDL] (لغة تعريف البيانات) الخاصة بالجدول [ARTICLES]:

    يقدم هذا الرمز SQL لتوليد الجدول مع جميع قيوده. يمكن حفظ هذا الرمز في برنامج نصي لإعادة تشغيله لاحقًا:

    SET SQL DIALECT 3;
SET NAMES NONE;
CREATE TABLE ARTICLES (
    ID            INTEGER NOT NULL,
    NOM           VARCHAR(20) NOT NULL,
    PRIX          DOUBLE PRECISION NOT NULL,
    STOCKACTUEL   INTEGER NOT NULL,
    STOCKMINIMUM  INTEGER NOT NULL
);
ALTER TABLE ARTICLES ADD CONSTRAINT CHK_ID check (ID>0);
ALTER TABLE ARTICLES ADD CONSTRAINT CHK_PRIX check (PRIX>0);
ALTER TABLE ARTICLES ADD CONSTRAINT CHK_STOCKACTUEL check (STOCKACTUEL>0);
ALTER TABLE ARTICLES ADD CONSTRAINT CHK_STOCKMINIMUM check (STOCKMINIMUM>0);
ALTER TABLE ARTICLES ADD CONSTRAINT CHK_NOM check (NOM<>'');
ALTER TABLE ARTICLES ADD CONSTRAINT UNQ_NOM UNIQUE (NOM);
ALTER TABLE ARTICLES ADD CONSTRAINT PK_ARTICLES PRIMARY KEY (ID);

    2.5. إدخال البيانات في الجدول

    حان الوقت الآن لإدخال البيانات في الجدول [ARTICLES]. وللقيام بذلك، سنستخدم لوحة التحكم الخاصة به [Data]:

    يتم إدخال البيانات بالنقر المزدوج على حقول الإدخال في كل سطر من الجدول. يتم إضافة صف جديد باستخدام الزر [+]، وحذف صف باستخدام الزر [-]. تتم هذه العمليات ضمن معاملة يتم تأكيدها بواسطة الزر [Commit Transaction] (انظر أعلاه). وبدون هذا التأكيد، ستُفقد البيانات.

    2.6. المحرر SQL الخاص بـ [IB-Expert]

    تتيح لغة SQL (لغة الاستعلام الهيكلية) للمستخدم ما يلي:

    1. إنشاء جداول مع تحديد نوع البيانات التي ستخزنها، والقيود التي يجب أن تستوفيها هذه البيانات
    1. إدراج البيانات فيها
    2. تعديل بعضها
    3. حذف بيانات أخرى
    4. استخراج المحتوى منها للحصول على معلومات
    5. ...

    يتيح IBExpert للمستخدم إجراء العمليات من 1 إلى 4 بطريقة رسومية. وقد رأينا ذلك للتو. عندما تحتوي قاعدة البيانات على العديد من الجداول التي تحتوي كل منها على مئات الأسطر، نحتاج إلى معلومات يصعب الحصول عليها بصريًا. لنفترض على سبيل المثال أن متجرًا إلكترونيًا على الويب يستقبل آلاف المشترين شهريًا. يتم تسجيل جميع عمليات الشراء في قاعدة بيانات. بعد ستة أشهر، نكتشف أن المنتج «X» معيب. نرغب في الاتصال بجميع الأشخاص الذين اشتروه حتى يعيدوا المنتج لاستبداله مجانًا. كيف يمكن العثور على عناوين هؤلاء المشترين؟

    1. يمكننا الاطلاع بصريًّا على جميع الجداول والبحث عن هؤلاء المشترين. سيستغرق ذلك بضع ساعات.
